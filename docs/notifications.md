# 通知の設計（9章）

通知はすべて端末の中で作るローカル通知です。サーバーからのプッシュ通知は使いません。

- 予定を組み立てる：`NotificationPlanner`（純粋な関数。テストで確かめる）
- 許可と登録：`NotificationScheduler`（`UNUserNotificationCenter` を扱う）
- 通知のタップ：`AppDelegate` → `AppRouter.openNotification`

## 通知の種類

| 種類 | タイミング | 対象 | 文面 | 無料/プラス |
|---|---|---|---|---|
| 支払日の前日（`payment`） | 支払日の前日 9:00 | 契約中のサブスク。月額は3回先まで、年額は次の1回 | 「明日は「◯◯」の支払日です」「1,490円（毎月）の支払いが予定されています。」 | 無料 |
| トライアル終了（`trial`） | 終了日の3日前と前日の 9:00 | トライアル終了日を入れた契約中のサブスク | 「「◯◯」の無料トライアルがあと3日で／明日で終わります」 | プラスのみ |
| 月次チェックイン（`checkIn`） | 毎月1日 20:00 | 聞くサブスクがあるとき | 「月次チェックインの時間です」「先月どのサブスクを使ったか、1件ずつ答えて振り返りましょう。」 | 無料 |

- 月額を3回先まで登録するのは、アプリを開かない月があっても通知が届くようにするためです
- 通知の時刻を過ぎたもの（今日の 9:00 を過ぎた前日通知など）は登録しません
- 支払日が古いまま保存されていても、今日以降の支払日から計算します

## 月次チェックインの通知

登録から1ヶ月未満のサブスクはチェックインで聞かないため、聞くものがない月は通知しません。

- 次の1日（20:00）に聞けるサブスクがある → 毎月1日 20:00 に繰り返す通知（識別子 `checkIn.monthly`）
- 次の1日にはまだ聞けない → 聞けるようになる最初の1日に1回だけの通知（識別子 `checkIn.first`）
  - 例：9月26日に初めて登録した → 10月1日は通知せず、11月1日 20:00 に通知
  - その後アプリを開くと（通知のタップを含む）登録し直され、毎月の繰り返しに切り替わります
- 契約中のサブスクがなければ登録しません

## 上限64件の扱い

iOS が1つのアプリに登録できるローカル通知は64件までです。

1. チェックインの通知（1件）は必ず登録する
2. 残りの63件に、支払い・トライアルの通知を日時の近い順に入れる

登録の数が多くても、直近の予定から届きます。アプリを開くたびに登録し直すので、先の予定も順に入っていきます。

## 通知の識別子

| 種類 | 識別子 |
|---|---|
| 支払日の前日 | `payment.<サブスクID>.<支払日の UNIX 秒>` |
| トライアル終了 | `trial.<サブスクID>.<何日前>` |
| チェックイン（繰り返し） | `checkIn.monthly` |
| チェックイン（初回の1回） | `checkIn.first` |

通知の `userInfo` には種類（`kind`）とサブスクID（`subscriptionID`）を入れ、`threadIdentifier` を種類ごとに分けて、通知センターでまとまるようにしています。

## 登録し直すタイミング

登録し直すときは、登録済みの通知をすべて消してから、今の予定で登録します。

| きっかけ | 呼び出し元 |
|---|---|
| データの保存（追加・編集・解約・削除・チェックイン・全削除） | `ModelContext.didSave` の監視（`NotificationScheduler.init`） |
| アプリの起動・フォアグラウンド復帰 | `RootView`（`scenePhase` が `.active`） |
| サブスク帳プラスの状態の変化 | `RootView`（`entitlements.isPremium` の変化） |
| 通知の ON/OFF の切り替え | `SettingsNotificationSection` |
| 通知の許可 | `NotificationScheduler.requestAuthorization` |

続けて呼ばれた場合は、前の処理を取り消し、300ミリ秒待ってから最後の1回だけ行います。前の処理が止まるのを待ってから始めるので、古い予定が後から追加されることはありません。

通知が許可されていなければ、消すだけで登録はしません。

## 通知の許可

- オンボーディングの2ページ目で、理由を説明してから許可のダイアログを出します（「あとで」で飛ばせる）
- 設定画面の「通知」から、あとで許可できます。拒否済みの場合は「設定アプリを開く」を表示します

## 通知をタップしたとき

| 種類 | 開く画面 |
|---|---|
| チェックイン | ホームに切り替えて、チェックインを全画面で開く |
| 支払い・トライアル | 一覧を開く |

登録・編集画面やペイウォールを開いていた場合は、閉じてから表示します。アプリを開いている間に届いた通知も、バナーで表示します。

## 通知の設定

設定画面で種類ごとに ON/OFF できます（既定はすべて ON）。値は UserDefaults の `notifications.*` に保存します。トライアル終了の通知は、無料プランではスイッチの代わりに「プラス」のバッジを表示し、タップするとペイウォールを開きます。

## 確認方法

Debug ビルドの設定画面「デバッグ → 登録済みの通知」で、登録されている通知の文面と次に届く日時を確認できます。
